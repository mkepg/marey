# Phase 9C Documentation Site and Gallery Implementation Plan

**Goal:** A static documentation site beside the playground: a 14-lesson
course with live, editable samples; a 22-scene gallery; six task guides; and
the reference rendered from the repository and the compiler's contract. It is
generated by the repository's own build and checked by it.

**Architecture:** A Vite plugin (`vite-plugins/site.ts`) calls a small
generator (`site/build/`) that turns Markdown with front matter into complete
HTML pages. They are virtual HTML entries in `vite build`, and the plugin
serves them from middleware in development. Every page loads one client
module (`site/client/main.ts`), which adds the live samples, search, theme,
navigation and the player pool. Marey code is highlighted by the compiler's own
lexer (`site/shared/highlight.ts`), and every sample is compiled at build time.

**Tech stack:** TypeScript, Vite 8 (beta, as pinned), `marked@18.1.2` (new dev
dependency, exact pin), Vitest, Playwright for the browser check, and the
repository's own compiler and `<marey-player>`.

**Spec:** `docs/specs/2026-11-13-marey-phase-9c-docs-site-and-gallery-design.md`.
This plan starts after the fitted-keyframes Lottie work has merged (spec C22).

- Every commit passes the four `AGENTS.md` checks: `npm test`, `npx vitest run --config eval/vitest.config.ts`, `npm run build`, and `npm run build:cli && node bin/marey.mjs check $(git ls-files '*.marey')`.
- Run Vitest from a working directory spelled with a capital `C:` (engineering lessons §6).
- Stage paths explicitly and read `git diff --staged` before committing. Never `git add -A`, `git add .` or `git add -f`.
- Commit subjects are Conventional Commits with scope `9c`, for example `feat(9c): ...`. No trailers naming a tool or assistant.
- Committed text, site content included, describes the engineering only. It never mentions an assistant, a skill, a plan-execution mode or a tool-specific path. No sales language.
- `core.autocrlf` is on. Judge what changed with `git diff --stat -- <path>`, not `git status`.
- For browser work: `npx vite --port 5199 --strictPort` (or `npx vite preview --port 5199 --strictPort` for the production check). Kill it afterwards and confirm the port is free.
- The playground at `/` keeps working unchanged apart from the two top-bar links (spec C17). Do not change `netlify.toml`. Do not add `public/_redirects`.
- No change to anything shipped in `marey-lang`: `src/player/`, `src/compiler/` (except the two `LANGUAGE.md` passages and the `determinism.md` fence tags, which are docs), `bin/`, and the build configs other than `vite.config.ts`. `npm run check:pack` still reports 127 files at version 0.7.0.
- Site client code never imports `monaco-editor`, directly or indirectly.
- Fence info strings allowed in site content: `marey`, `marey error=CODE`, `marey error`, `marey fragment`, `marey solution`, `text`, `bash`, `html`, `yaml`, `json`. Anything else fails the build.
- Every gallery scene has a finite `duration` and passes `node bin/marey.mjs check --export-ready`.
- Scene size for lessons and showcases is `960x540` unless a brief says otherwise.
- A showcase uses only vocabulary introduced up to and including its own lesson (the `site.json` vocabulary lists below).
- Do not push, tag or publish.

## Review Focus

- **Text in a sample that looks like HTML** (`content: "<b> & </b>"`, a `</script>` inside a string): it must render as text, round-trip through the editor and the share link unchanged, and never break the page. Task 2 pins the build side and Task 4 the client side.
- **An edit that does not lex** (an unclosed string, a stray `@`): the highlighter must still show the text, the error list must show the lexer's message, and the editor must not lose characters. Task 2 (highlighter) and Task 4 (editor) pin it.
- **A blocked `localStorage`** (private mode, storage disabled): theme, progress and every other feature still work, with nothing remembered. Task 3 pins it.
- **Fast navigation on a long page**: scrolling the gallery quickly up and down must never hold more than 12 players or leak a WebGL context, and a player removed mid-load must not throw. Task 4 pins the pool, and Task 15's check measures it.
- **A narrow phone (360 px) on a lesson**: no horizontal page scroll, a usable editor, a toolbar that wraps, and a sidebar reachable from its button. Task 3 pins the layout, and Task 15 measures it.

## Shared definitions

Later tasks use these names. Task 1 creates them.

`site/site.json`, shown with one entry per list for its shape. Task 1 writes it with
every list empty, and each task appends the entries for the pages it adds, so
navigation integrity holds at every commit:

```json
{
  "learn":     [{ "slug": "first-scene", "vocabulary": ["scene", "…"] }],
  "guides":    ["install"],
  "reference": ["language", "properties", "determinism"],
  "gallery":   ["lighthouse"]
}
```

A lesson's number is its index in `learn` plus 1.

The vocabulary per lesson is fixed here, so every lesson task uses the same
lists. It covers keywords, shape kinds, property names and keyword values:

| # | slug | vocabulary |
|---|---|---|
| 1 | `first-scene` | `scene size background duration circle rectangle position radius color animate property to` |
| 2 | `shapes` | `polygon line text points thickness content fontSize alpha rotation origin layer fit contain cover fill none` |
| 3 | `animate` | `easing linear easeIn easeOut easeInOut scale` |
| 4 | `timing` | `loop yoyo delay true false` |
| 5 | `groups` | `group` |
| 6 | `sequence` | `sequence parallel` |
| 7 | `colour` | (none) |
| 8 | `values` | `let if then else and or not sin cos length` |
| 9 | `generate` | `generate in` |
| 10 | `templates` | `template use` |
| 11 | `physics` | `physics gravity velocity bounce airDrag collideBounds indefinitely` |
| 12 | `world` | `world bounds lockPosition lockRotation spin left right top bottom` |
| 13 | `handoff` | `handoff` |
| 14 | `ship-it` | (none) |

The words checked in a showcase are: every `KEYWORD`, `EXPR_KEYWORD`, `EASING`,
`FIT`, `BOOLEAN` and `DURATION_INDEFINITELY` token's value, and every `IDENT`
token directly followed by a `COLON` token (a property name), plus the edge
words inside a `bounds` list.

The page model, in `site/build/types.ts`:

```ts
export type Section = "learn" | "guides" | "gallery" | "reference" | "root";
export interface Heading { readonly depth: 2 | 3; readonly text: string; readonly id: string }
export interface SitePage {
  readonly url: string;        // "/learn/animate/"
  readonly outFile: string;    // "learn/animate/index.html"
  readonly section: Section;
  readonly title: string;
  readonly description: string;
  readonly html: string;       // the complete document
  readonly headings: ReadonlyArray<Heading>;
  readonly text: string;       // plain text for search, by heading
  readonly links: ReadonlyArray<{ readonly href: string; readonly line: number; readonly file: string }>;
}
export interface BuiltSite {
  readonly pages: ReadonlyArray<SitePage>;
  readonly errors: ReadonlyArray<string>;   // "file:line: message"
  readonly sitemap: string;
  readonly searchIndex: string;             // JSON
}
export function buildSite(repoRoot: string): BuiltSite;   // in site/build/index.ts
```

The HTML contract between the generator (Task 2) and the client (Task 4) for
a sample:

```html
<figure class="sample" data-mode="live|run|error|fragment|solution|showcase"
        data-source="…HTML-escaped Marey source…"
        data-playground="https://marey.pages.dev/#…">
  <div class="sample-stage"></div>                      <!-- absent for error and fragment -->
  <pre class="code" data-lang="marey"><code>…highlighted…</code></pre>
  <ol class="sample-errors">…</ol>                      <!-- error mode only, prerendered -->
</figure>
```

- A `solution` sample sits inside `<details class="solution"><summary>Show a solution</summary>…</details>`.
- An exercise is `<section class="try">` with an `h3` title.
- A callout is `<aside class="callout callout-note|tip|warn">`.
- Highlighted tokens are `<span class="tk-K">`, where K is one of `keyword`, `prop`, `ident`, `number`, `string`, `color`, `const` (easing, fit, boolean, indefinitely), `op` (expression words), `punct`, `comment` and `error`.
